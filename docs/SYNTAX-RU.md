## 1. Командная строка

```
pdpy11 [-o outfile] [--bin | --raw | --sav | --wav | --turbo-wav] [--link N] [--play | --play-turbo]
       [--lst] [--implicit-bin] [--charset encoding] [--source-charset encoding]
       [--report-format graphical|bare] [-W xxx] [--version] infile [infile ...]
```

| Параметр | Значение |
|---|---|
| `infile ...` | исходные файлы. Несколько файлов компилируются как одна программа, один за другим |
| `-o outfile` | имя выходного файла. `-o -` пишет его в стандартный вывод |
| `--bin` | записать файл `.bin`: 4-байтовый заголовок (адрес загрузки, длина) и за ним образ |
| `--raw` | записать «голый» образ, без заголовка |
| `--sav` | записать файл RT-11 `.sav` (см. [10](#10-форматы-выходных-файлов)) |
| `--wav`, `--turbo-wav` | записать программу как ленточную запись для БК (обычный или турбо-формат) |
| `--link N` | адрес компоновки по умолчанию, восьмеричный (допустимы префиксы `0x`, `0o`, `0b` и точка в конце для десятичного). По умолчанию `1000`. `.link` в исходном тексте имеет приоритет |
| `--play`, `--play-turbo` | проиграть программу через звуковой выход в ленточном формате БК |
| `--implicit-bin` | если выходной файл не запрошен ни в исходном тексте (`make_*`), ни в командной строке, записать `<исходник>.bin` |
| `--lst` | записать файл листинга рядом с выходным файлом |
| `--charset enc` | кодировка строк в выходном файле: `bk` (по умолчанию, набор символов БК на основе КОИ-8), `koi8-r`, `cp1251`, `utf-8` |
| `--source-charset enc` | кодировка исходных файлов: `auto` (по умолчанию, определяется отдельно для каждого файла), `utf-8`, `utf-16`, `cp1251`, `cp866`, `koi8-r`, `latin-1` |
| `--report-format` | `graphical` (цвета и фрагменты исходного текста, по умолчанию) или `bare` (одна строка на сообщение: `file:line:column: Error: text`, удобно для редакторов) |
| `-W xxx` | включить предупреждение `xxx`; `-Wno-xxx` выключает его; `-Wall` включает все; `-Wdefault` — набор по умолчанию (см. [12](#12-диагностика)) |

Если в исходном тексте нет директивы `make_*` и не указаны ни `-o`, ни `--implicit-bin` (ни параметр формата),
программа только проверяется, и ничего не записывается. Код возврата равен `0`, если ошибок нет, и `1` в противном случае.

## 2. Структура программы

Программа — это последовательность **операторов**, по одному в строке. Оператор — это одно из следующего:

```
label:                    определение метки (перед оператором может стоять несколько меток)
name = expression         определение константы
instruction operands      инструкция (раздел 7)
.directive arguments      директива (раздел 8)
```

* Имена инструкций, директив, регистров и символов **не зависят от регистра букв**: `MOV`, `Mov` и `mov` — одно и то же.
  (Исключение — содержимое строк.)
* Комментарии: `; до конца строки`, `// до конца строки` и `/* блочный комментарий */`.
* Операнды разделяются запятыми. Начальную точку директивы в некоторых случаях можно опустить, но ассемблер
  предупредит об этом (`-Wmeta-typo`); всегда пишите точку.
* Пробельные символы между лексемами произвольны; оператор заканчивается в конце строки.
* Слова и инструкции должны лежать по чётным адресам. Если `.word` или инструкция попадает на нечётный адрес,
  выдаётся ошибка (и вставляется нулевой байт, чтобы компиляция могла продолжиться). После байтовых данных
  используйте `.even`.

```asm
        .link 1000
Start:  mov     #msg, r1            ; загрузить адрес строки
1:      movb    (r1)+, r0
        beq     2
        emt     16
        br      1
2:      halt
msg:    .asciz  "Hello"
        .even
```

## 3. Числа, символы и строки

### Числа

| Форма | Пример | Основание |
|---|---|---|
| `1234` | `1777` | **восьмеричное** (традиция PDP-11) |
| `1234.` | `1024.` | десятичное (точка в конце) |
| `0o1234`, `^O1234` | `0o17`, `^O17` | восьмеричное |
| `0x1234`, `^X1234` | `0x1f`, `^XFF` | шестнадцатеричное |
| `0b1010`, `^B1010` | `0b101` | двоичное |
| `^D1234` | `^D10` | десятичное |
| `^O<377>`, `^X<ff>`, … | `^O<377>` | цифры можно заключать в угловые скобки |

Число без точки, содержащее цифры 8 или 9, — ошибка с подсказкой «add a dot to make it decimal» (добавьте точку,
чтобы число стало десятичным). `0` с последующими цифрами (`017`) — тоже восьмеричное число.

#### Основание по умолчанию: `.radix`

`.radix n` меняет основание чисел, записанных **без** префикса и без точки в конце, для всего текста ниже (как в
MACRO-11). `n` равно 2, 8, 10 или 16 и всегда читается как десятичное число; `.radix` без аргумента возвращает 8.
По умолчанию используется 8, и в начале каждого исходного файла из командной строки основание снова становится
равным 8 (файл, подключённый через `.include`, продолжает работу с текущим основанием).

```asm
        .radix  10
        mov     #100, r0        ; 100 десятичное = 0144
        .word   10, 10.         ; 12 и 12 (восьмеричное)
        .radix  16
        .word   1F, 0FF         ; цифры a-f допустимы; число начинается с цифры (0FF, а не FF)
        .radix  8
        .word   17.             ; точка, ^D, ^O, ^X, ^B, 0x, 0b работают при любом основании
```

- Число с точкой в конце всегда десятичное; числа с префиксом (`^D`, `^O`, `^X`, `^B`, `0x`, `0o`, `0b`) сохраняют своё
  основание.
- При основании 16 слово, состоящее только из шестнадцатеричных цифр и начинающееся с цифры (`0b1`, `0d9`), —
  шестнадцатеричное число, а не число с префиксом `0b…`/`0d…`. Слово, начинающееся с буквы (`FF`, `A1`), по-прежнему
  является символом.
- Цифра, недопустимая при текущем основании (`2` при основании 2), — ошибка.
- `.radix` действует в момент чтения текста, как `.if` и макросы: в пропускаемой ветке `.if` он не вступает в силу,
  а тело макроса или `.rept` читается с тем основанием, которое действует в точке раскрытия. Числа в условиях `.if`
  подчиняются тому же основанию.
- На метки основание не влияет (локальная метка вроде `1:` остаётся меткой).

### Символы

* `'A` — код символа: `mov #'A, r0` загружает 101 (восьмеричное). Закрывающей кавычки нет.
* `"AB` — 16-битное слово из двух символов; первый символ лежит в младшем байте: `"AB` = `0x4241`.
* Символы преобразуются в выходную кодировку (`--charset`, по умолчанию `bk`).
* Закрывающая кавычка (`'A'`) допускается и даёт предупреждение `-Wexcess-quote`.

### Строки

Строки пишутся в двойных кавычках: `"text"`. Escape-последовательности: `\n`, `\r`, `\t`, `\\`, `\"`, `\'`,
`\xHH` (две шестнадцатеричные цифры). Строки используются в `.ascii`, `.asciz`, `.rad50`, `.include`, `insert_file` и
директивах `make_*`. `.ascii` также принимает значения байтов в угловых скобках, которые можно сочетать со строками:
`.ascii <15><12>"Done"`.

## 4. Выражения

Выражение строится из чисел, символов, имён, счётчика адреса `.` и перечисленных ниже операторов. Скобки группируют
подвыражения. Операторы перечислены по порядку от **наиболее приоритетных** к наименее приоритетным:

| Уровень | Операторы | Значение |
|---|---|---|
| 1 | `+x` `-x` `~x` `^Cx` | унарный плюс, отрицание, побитовое дополнение (`^C` — синоним `~`) |
| 2 | `*` `/` `%` | умножение, целочисленное деление (с округлением вниз), остаток |
| 3 | `+` `-` | сложение, вычитание |
| 4 | `<<` `>>` `_` | сдвиг влево, сдвиг вправо и `a _ b`: сдвиг влево на *b*, а при отрицательном *b* — вправо |
| 5 | `&` | побитовое И |
| 6 | `^` | побитовое исключающее ИЛИ |
| 7 | `\|` `!` | побитовое ИЛИ (`!` — написание из MACRO-11) |

Операторы одного уровня вычисляются слева направо. Порядок тот же, что в Си и Python, для общих операторов:
`1<<2+1` — это `1<<(2+1)` = 8, а `1|2^3&4` — это `1|(2^(3&4))`. (MACRO-11 и Turbo8 отличаются: там `+`, `-`,
`*`, `/`, `&` и `!` образуют один уровень и вычисляются слева направо.)

```asm
A = (B + C / 2) * 2 + 7 * 3        ; любое математическое выражение
.word 6&3|10, 1<<4, 100 _ -2
```

При вычислении значения — 64-битные целые; при сохранении они должны помещаться в поле (`.byte` — 8 бит, `.word` —
16 бит, …), иначе выдаётся ошибка «does not fit». Отрицательное число тоже помещается (`.word -1` даёт `177777`).

Счётчик адреса `.` — это адрес текущего оператора: `.word .` сохраняет собственный адрес, `br .` — бесконечный
цикл, а `. = 3000` (или `.link 3000`) перемещает его (см. [8](#8-директивы)).

## 5. Символы и метки

### Константы

```asm
size = 40
total = size * 2 + 1
```

Константа определяется один раз; повторное определение — ошибка «Duplicate variable». Значение может зависеть от
меток и от констант, определённых ниже: PDPy11 вычисляет всё после чтения всей программы.

```asm
A = B + 100
B = 200 + C
C = L2 - L1
L1: .blkw 100
L2:
```

Циклическое определение (`x = x`, `a = b`, `b = a`) считается ошибкой.

### Метки

* **Глобальная метка** — это имя с двоеточием: `Loop:`. Имена состоят из букв, цифр, `_`, `$` и `.` и не могут
  начинаться с цифры (имя, начинающееся с цифры, — локальная метка). Повторное определение — ошибка («Duplicate symbol»).
* **Локальная метка** — это имя, которое **начинается с цифры**, с двоеточием: `1:`, `2x:`, `10_loop:`, `1abc$:`.
  После первой цифры имя может содержать буквы, цифры, `_`, `$` и `.`, как и глобальная метка. Локальная метка
  видна до следующей обычной (глобальной) метки, поэтому в каждой подпрограмме можно повторно использовать одни и те же
  имена; повторное определение того же имени в одной области видимости — ошибка «Duplicate local label». `br 1` и
  `jmp (1:)` ссылаются на `1:` текущей области видимости, расположена ли она выше или ниже инструкции. Чисто
  числовое имя (`1`) нужно записывать с двоеточием или в адресе перехода, чтобы оно считалось меткой (см.
  [Локальные метки в арифметике](#локальные-метки-в-арифметике)); имя с буквами (`1abc`) не может быть числом, поэтому
  его можно писать без двоеточия: `br 1abc`.
* Локальная метка другой области видимости записывается как `Name:N` (без пробелов): это локальная метка `N:`,
  следующая за глобальной меткой `Name:`. Символ другого файла записывается как `Name:Label`: метка `Label` того
  файла, в котором определена метка `Name` (см. [Составные имена](#составные-имена-namen-и-namelabel)).
* Метка с двумя двоеточиями, `name::`, — **внешняя**: она видна в других файлах программы (см.
  [9](#9-файлы-компоновка-и-видимость)). Локальная метка не может быть внешней (`1::` — ошибка «A local label cannot be
  external»).

### Составные имена: `Name:N` и `Name:Label`

Область видимости локальной метки начинается после глобальной метки и заканчивается на следующей глобальной метке.
Чтобы сослаться на локальную метку `N:` этой области из любого места, напишите глобальную метку, открывающую область,
двоеточие и номер без пробелов: `Name:N`.

```asm
Metka:  nop
1:      nop
2:      nop
        jmp  Metka:2        ; назад, область видимости Metka:
Other:  nop
1:      nop                 ; другая метка 1: (область видимости Other:)
        jmp  @#Metka:2      ; метка 2: из Metka:, хотя текущая область — Other:
        jmp  Last:1         ; вперёд, в область, определённую ниже
        .word Metka:1, Other:1, Metka:2 - Metka:1
Last:   nop
1:      nop
```

* Это работает везде, где допустимо выражение: в операндах инструкций (`jmp Metka:2`, `br Metka:1`, `mov #Metka:2, r0`),
  в `.word`, в выражениях со скобками и арифметических выражениях; ссылки вперёд и назад работают одинаково.
* `Name` должно быть глобальной меткой (или глобальной меткой, открытой через `::` или `.extern`; тогда форма работает
  и из других файлов: `Start::` в одном файле, `Start:2` в другом). Если `Name` — не метка, закрытая метка другого
  файла или после `Name:` нет `N:`, выдаётся ошибка «Local label 'Name:N' is not defined».
* Число должно следовать за двоеточием сразу: `Metka:2` — это ссылка, а `Metka: 2` — метка `Metka:`, за которой идёт
  что-то другое.
* В `1: … br 1` и в `(1:)` имеется в виду текущая область видимости; `Name:N` нужна только для другой области.

#### `Name:Label`: символ другого файла

Если вторая часть — не число, `Name:Label` означает символ `Label` (метку или константу) **того файла**, в котором
определена метка `Name`. Эта форма нужна, когда в одну программу собрано несколько файлов (библиотек) с одинаковыми
внутренними именами, например `Init`:

```asm
; main.mac
        .include "play.mac"
        .include "load.mac"
        call    Play:Init       ; Init из play.mac
        call    Load:Init       ; Init из load.mac

; play.mac                      ; load.mac
Play::  nop                     Load::  nop
Init:   nop                     Init:   nop
```

Экспортируйте (через `::` или `.extern`) только по одной метке каждого файла, с именем, уникальным в программе
(`Play`, `Load`), и обращайтесь к остальным через неё. Закрытые метки `Init` друг с другом не конфликтуют.

* `Name` должно быть меткой. `Label` ищется среди символов того файла, в котором определена `Name`, общих или
  закрытых; учитывается весь файл, а не только часть ниже `Name`.
* Имена не зависят от регистра букв, как и все символы. Вокруг двоеточия нет пробелов.
* Допускается только один уровень: `A:B:C` и `A:B:1` — ошибка («Only one level is allowed»).
* Форма работает и в том же файле (`Play:Init` внутри play.mac). Отсутствующая метка даёт «Symbol 'Name:Label'
  is not defined».
* `Name:Label` — это только **ссылка**; она никогда не определяет метку. Несколько меток подряд пишутся через пробельный
  символ: `A: B: nop`. Запись без пробелов, `A:B: nop`, — ошибка `label-chain` («Several labels in a row
  must be separated by whitespace … Write 'A: B:' instead»), потому что она похожа на составное имя. `Loop:nop` (метка,
  сразу за которой идёт инструкция) по-прежнему допустима.

### Локальные метки в арифметике

Голое число в качестве адреса перехода — это *локальная метка*; в других контекстах это обычное число. Чтобы смешать
оба случая, добавьте двоеточие или скобки:

```asm
1:
2:
        br   1            ; локальная метка 1:
        br   1 - 2        ; локальная метка 1: минус 2 байта  (предупреждение -Wlabel-fixup)
        br   (1)          ; глобальный адрес 1
        br   (1 - 2)      ; глобальный адрес 177777
        br   (1:)         ; локальная метка 1:
        br   (1: - 2)     ; локальная метка 1: минус 2 байта
        br   (1: - 2:)    ; локальная метка 1: минус локальная метка 2:
        jmp  1            ; глобальный адрес 1 (JMP принимает адрес, а не смещение)
        jmp  (1:)         ; локальная метка 1:
```

(Строки выше показывают, как разбирается каждая форма; в реальной программе некоторые из них оказались бы за пределами
диапазона ветвления.)

Обычно нужны только `br label`, `br label ± offset` и `jmp global_address`. Добавляйте двоеточие всякий раз, когда
хотите использовать локальную метку внутри более сложного выражения.

## 6. Операнды и режимы адресации

Регистры: `r0`–`r7`, где `sp` = `r6` и `pc` = `r7`; `%0`–`%7` — те же регистры, записанные числами.
Аккумуляторы с плавающей точкой: `ac0`–`ac5`.

| Режим | Синтаксис | Пример |
|---|---|---|
| Регистровая | `Rn` | `clr r0` |
| Регистровая косвенная | `(Rn)` | `clr (r1)` |
| Автоинкрементная | `(Rn)+` | `mov (r1)+, r0` |
| Автоинкрементная косвенная | `@(Rn)+` | `mov @(r2)+, r0` |
| Автодекрементная | `-(Rn)` | `mov r0, -(sp)` |
| Автодекрементная косвенная | `@-(Rn)` | `clr @-(r2)` |
| Индексная | `E(Rn)` | `clr 2(r3)`, `clr table(r3)` |
| Индексная косвенная | `@E(Rn)` | `mov @4(r2), r0` |
| Непосредственная | `#E` | `mov #1000, r0` (значение следует за инструкцией: `(pc)+`) |
| Абсолютная | `@#E` | `mov @#177716, r0` (`@(pc)+`) |
| Относительная | `E` | `mov var, r0` (голое выражение — **PC-относительный** адрес: `E-.(pc)`) |
| Относительная косвенная | `@E` | `mov @ptr, r0` |

Примечания:

* Голое имя или выражение — это *относительная* адресация, поэтому код, обращающийся к собственным переменным,
  остаётся позиционно-независимым. Используйте `#E` для самого значения и `@#E` для фиксированного абсолютного
  адреса.
* `(E)` — регистр только тогда, когда `E` — имя регистра; `(1000)` — выражение в скобках (обычное число).
* Инструкции вроде `bne`, `br`, `sob` принимают **смещения**: операнд — это адрес перехода, а смещение вычисляет
  ассемблер. Ветвление достигает ограниченного расстояния (−128 … +127 слов); `sob` прыгает только назад.
  Выход за диапазон и нечётные смещения считаются ошибками.
* Инструкции с плавающей точкой принимают аккумулятор `ac0`–`ac5` или, если инструкция это допускает, любой режим
  адресации процессора; обычный регистр `r0`–`r3` на месте аккумулятора трактуется как `ac0`–`ac3` с примечанием.

## 7. Инструкции

Имена инструкций и операнды соответствуют стандартным мнемоникам PDP-11 (синтаксис DEC, сначала источник, затем
приёмник): `mov src, dst`, `add src, dst`, `jsr reg, dst`, `sob reg, label`, `mul src, reg`, `xor reg, dst`, `emt n`,
`trap n`, …

Группы, известные ассемблеру (здесь все имена записаны строчными буквами, в программе допустим любой регистр):

| Группа | Инструкции |
|---|---|
| Управление | `halt wait rti rtt bpt iot reset nop mfpt` и специфичные для моделей `start step rd urd rdpc rdps uwr wrpc wrps spl csm tstset wrtlck` |
| Коды условий | `clc clv clz cln ccc sec sev sez sen scc` и их комбинации (`clzc`, `senv`, …) |
| Ветвления | `br bne beq bge blt bgt ble bpl bmi bhi blos bvc bvs bcc bhis bcs blo` |
| Один операнд | `clr com inc dec neg adc sbc tst ror rol asr asl swab sxt mfpi mtpi mfpd mtpd jmp` и байтовые формы `clrb comb incb decb negb adcb sbcb tstb rorb rolb asrb aslb` |
| Слово состояния процессора | `mtps mfps` |
| Два операнда | `mov cmp bit bic bis add sub` и `movb cmpb bitb bicb bisb` |
| Подпрограммы | `jsr rts mark sob emt trap` |
| EIS | `mul div ash ashc xor` |
| FIS | `fadd fsub fmul fdiv` |
| FP11 | `ldf ldd stf std addf addd subf subd mulf muld divf divd cmpf cmpd tstf tstd absf absd negf negd modf modd clrf clrd ldfps stfps stst cfcc setf setd seti setl ldexp stexp ldcif ldcid ldclf ldcld ldcfd ldcdf stcfi stcfl stcdi stcdl stcfd stcdf` |
| Коммерческие / символьные | `movc movrc movtc locc skpc scanc spanc cmpc matc addn subn cmpn …` (набор CIS, с вариантами `…i`) |

Удобные псевдонимы:

| Псевдоним | Равносилен |
|---|---|
| `push x` | `mov x, -(sp)` |
| `pop x` | `mov (sp)+, x` |
| `call x` | `jsr pc, x` |
| `callr x` | `jmp x` |
| `ret`, `return` | `rts pc` |
| `sys n` | `trap n` |
| `hlt` | `halt` |

Диапазоны операндов проверяются (например, `emt` и `trap` принимают 8-битное число, `mark` — 6-битное, `sob` прыгает
назад не более чем на 63 слова), а нарушения сопровождаются сообщением.

## 8. Директивы

Имена директив начинаются с точки. Они не зависят от регистра букв.

### Данные

| Директива | Действие |
|---|---|
| `.byte n, …` (`.db`) | записать байты. Значение должно помещаться в 8 бит (отрицательное число берётся как дополнительный код) |
| `.word n, …` (`.dw`) | записать 16-битные слова (порядок байтов little-endian). Адрес должен быть чётным |
| `.dword n, …` | записать 32-битные значения как два слова, старшее слово первым |
| `.ascii "text"` | записать байты текста (в выходной кодировке). Можно подмешивать значения байтов в `<…>` |
| `.asciz "text"` | то же плюс нулевой байт |
| `.rad50 "text"` | упаковать текст в слова RADIX-50 (3 символа на слово; алфавит: пробел, `A`–`Z`, `$`, `.`, `0`–`9`) |
| `.blkb n` | зарезервировать *n* нулевых байтов |
| `.blkw n` | зарезервировать *n* нулевых слов |
| `.even` | если адрес нечётный, добавить один нулевой байт |
| `.odd` | если адрес чётный, добавить один нулевой байт |
| `.align n` | дополнить нулевыми байтами до кратного *n* |
| `insert_file "file"` | вставить содержимое двоичного файла |

### Размещение и управление потоком

| Директива | Действие |
|---|---|
| `.link addr` (или `. = addr`) | задаёт адрес, с которого программа **компонуется** (загружается); по умолчанию `1000`. Первая такая директива главного файла задаёт адрес загрузки всей программы, даже если перед ней есть код. Следующая сдвигает счётчик адреса вперёд и заполняет промежуток нулевыми байтами; сдвиг назад — ошибка |
| `.include "file"` | скомпилировать другой исходный файл в этом месте (путь отсчитывается от текущего файла) |
| `.once` | файл можно подключить только один раз; последующие `.include` этого файла ничего не делают |
| `.extern name, …` / `.extern all` | символы, видимые другим файлам (см. [9](#9-файлы-компоновка-и-видимость)) |
| `.repeat n { … }` | повторить операторы в фигурных скобках *n* раз |
| `.end` | прекратить чтение этого файла. Внутри `.repeat` завершает текущее повторение (как `continue`) |
| `.error "text"` | выдать ошибку с этим текстом (полезно в условном коде) |

Пример `.repeat`:

```asm
        .repeat 4 {
                .word 0
                nop
        }
```

### Принимаются и игнорируются

`.list`, `.nlist`, `.title`, `.sbttl`, `.ident`, `.page` разбираются, чтобы принимались исходные тексты для MACRO-11;
они ничего не делают и дают предупреждение `-Wnot-implemented`.

### Вывод (см. [10](#10-форматы-выходных-файлов))

`make_bin`, `make_bk0010_rom`, `make_raw`, `make_sav`, `make_wav`, `make_turbo_wav`, `play_wav`, `play_turbo_wav`.

## 9. Файлы, компоновка и видимость

Все файлы, названные в командной строке, и все файлы, подключённые через `.include`, образуют **одну программу**: код
каждого файла следует за кодом предыдущего. `.include` практически равносилен вставке подключаемого файла в это место.

**Адрес компоновки** — это адрес, с которого программа будет загружена (`.link`, `--link`, по умолчанию `1000`).
Счётчик адреса `.` всегда показывает адрес компоновки, поэтому метки содержат окончательные адреса, а абсолютные
ссылки работают.

Если подключаемый файл содержит собственный `.link`, `.` не перемещается: код файла по-прежнему размещается там, где
происходит подключение, но его метки вычисляются так, как если бы он был загружен с этого адреса:

```asm
; main.mac
        .link 1000
        .word 1
        .word 2
        .word 3
        .include "inc.mac"

; inc.mac
        .link 2000
A:      .word A

; результат (начиная с адреса 1000):   000001 000002 000003 002000
```

### Видимость символов

По умолчанию метки и константы файла видны только внутри этого файла; символ с тем же именем в другом файле — это
другой символ. `.extern` это меняет:

* `.extern name1, name2, …` делает эти символы общими с другими файлами;
* `.extern all` делает общими все символы файла;
* метка, определённая как `name::`, тоже становится общей; так же ведёт себя константа, определённая как
  `name == value`. Локальные метки общими быть не могут (`1::` — ошибка), но те из них, что следуют за общей меткой,
  доступны из других файлов как `name:N`, а любой другой символ файла — как `name:Label` (см.
  [Составные имена](#составные-имена-namen-и-namelabel)). Поэтому в файле библиотеки достаточно сделать общей одну
  метку с уникальным именем: остальное остаётся закрытым и не может конфликтовать с символами других файлов.

```asm
; a.mac                            ; b.mac
.extern LABEL_A                    LABEL_B = 3
LABEL_A = 1                        .word LABEL_A, LABEL_B
LABEL_B = 2
.word LABEL_A, LABEL_B
.include "b.mac"
.word LABEL_A, LABEL_B

; результат: 000001 000002 000001 000003 000001 000002
```

(`LABEL_A` общая, поэтому `b.mac` её видит; `LABEL_B` закрыта в каждом файле.)

### `.once` и файлы библиотек

Типичное применение `.include` — библиотека подпрограмм или констант. Поставьте `.once` в начале библиотеки, чтобы при
подключении её из нескольких файлов её метки не определялись дважды:

```asm
; lib/hdd.mac
        .once
HddRead: …
```

## 10. Форматы выходных файлов

| Формат | Параметр | Директива | Содержимое файла |
|---|---|---|---|
| `bin` | `--bin` | `make_bin ["file"]` / `make_bk0010_rom` | 2 байта адреса загрузки, 2 байта длины, затем образ (файл `.bin` для БК-0010) |
| raw | `--raw` | `make_raw ["file"]` | «голый» образ |
| `sav` | `--sav` | `make_sav ["file" [, final_address]]` | 512-байтовый заголовок RT-11 `.sav` (начальный адрес по 040, стек 01000 по 042, конечный адрес по 050, битовая карта блоков по 0360), за ним образ. `final_address` по умолчанию равен концу образа |
| WAV для ленты БК | `--wav` | `make_wav ["file.wav" [, "name on tape"]]` | запись `.wav`, которую БК загружает с ленточного входа |
| turbo WAV для БК | `--turbo-wav` | `make_turbo_wav ["file.wav" [, "name on tape"]]` | то же в турбо-формате |
| воспроизведение | `--play`, `--play-turbo` | `play_wav ["name on tape"]`, `play_turbo_wav [...]` | запись проигрывается через динамики вместо сохранения |

* Без имени файла вывод идёт в файл с именем исходного файла и заменённым расширением (`prog.mac` → `prog.bin`,
  `prog.sav`, `prog.wav`; у raw-вывода расширения нет).
* Директива в исходном тексте и параметр командной строки работают оба: параметр добавляет ещё один выходной файл.
  Если в исходном тексте есть хотя бы одна директива `make_*`, `.bin` по умолчанию не записывается, пока его не
  запросят.
* Имя на ленте — до 16 символов в выходной кодировке. Если оно не указано, оно образуется из имени выходного файла
  (для `play_*` — из имени исходного файла).
* `make_wav "~speaker"` проигрывает звук вместо записи файла (то же, что `play_wav`).
* `.sav` помещает образ сразу после заголовка независимо от адреса компоновки, как это делает оригинальный PDPy11.
* Звук воспроизводится средствами системы: PlaySound в Windows, `afplay` в macOS, `paplay` или `aplay` в Linux.
* `--lst` записывает листинг (`prog.lst`) с адресами меток.

## 11. Макросы и условная компиляция

В PDPy11 есть текстовые макросы (в стиле MACRO-11), условная компиляция и блоки повторения; они раскрываются при
чтении исходного текста. Полное описание — в [MACROS-RU.md](MACROS-RU.md); здесь дана краткая сводка.

```asm
; Psw равно 340 (прерывания запрещены), если не задано иное
	.macro	SetVec	Vec,Handler,Psw=340
		MOV	#Handler,@#Vec
		MOV	#Psw,@#Vec+2
	.endm

; ?Loop — уникальная метка для каждого вызова
	.macro	Delay	Count=1000,?Loop
		PUSH	R0
		MOV	#Count,R0
Loop:		SOB	R0,Loop
		POP	R0
	.endm

		SetVec	60,KeyIrq
		SetVec	100,Timer,200
		Delay				; 1000 итераций
		Delay	200
```

* `.macro name p1, p2=default, ?label` … `.endm`; `.mexit` досрочно прекращает раскрытие. Параметр, записанный как
  `?name`, получает уникальную локальную метку, если аргумент не задан.
* Аргумент, содержащий запятые, пишется в `<…>`. Макрос может вызывать другие макросы и самого себя (глубина ≤ 64).
* Апостроф склеивает параметр с соседним текстом: `x'y:` при `x=a`, `y=1` даёт `a1:`.
* Макросы из другого файла подключаются через `.include`; в библиотеке используйте `.once`.

Условная компиляция:

```asm
debug = 0                                 ; константа, определённая выше условия
        .if eq  debug                       ; также: ne gt lt ge le, b, nb, idn, dif, df, ndf
                nop
        .iff
                halt
        .endc
        .iif ne size, .word size            ; однострочная форма
```

`.irp`, `.irpc` и `.rept` повторяют блок до `.endr`. Условия вычисляются при чтении текста, поэтому проверять в них
можно только константы (`name = value`), определённые выше, и аргументы макросов, но не метки.

## 12. Диагностика

Сообщения имеют вид `file:line:column: Error|Warning: text` (при `--report-format bare`) или цветного фрагмента
исходного текста (по умолчанию). Ошибки делают код возврата равным `1`; после большинства ошибок компиляция
продолжается, чтобы за один запуск найти как можно больше проблем.

Предупреждения включаются и выключаются параметром `-W`:

```
pdpy11 -Wall prog.mac          # все предупреждения
pdpy11 -Wno-excess-hash prog.mac
pdpy11 -Wdefault -Wexcess-quote prog.mac
```

| Предупреждение | Включено по умолчанию | Значение |
|---|---|---|
| `implicit-operand` | да | операнд опущен, подразумевается ноль (`.byte` без значения) |
| `not-implemented` | да | директива принята, но игнорируется (`.list`, `.title`, …) |
| `label-fixup` | да | число, похожее на локальную метку, принято за неё (`br 1 - 2`); добавьте двоеточие или скобки |
| `excess-hash` | да | `#` у инструкции, неявно принимающей непосредственный операнд (`emt #5`) |
| `suspicious-name` | нет | метка, константа или операнд, похожие на инструкцию или регистр; обычно пропущен перевод строки или запятая |
| `excess-quote` | нет | закрывающая кавычка после символьной константы (`'A'`) |
| `meta-typo` | нет | директива, написанная без начальной точки |
| `legacy-deferred` | нет | устаревшая запись косвенной адресации |
| `implicit-index` | нет | формы `E(R)`, которые на самом деле означают индексную косвенную адресацию с нулевым смещением |
| `source-encoding` | нет | исходный текст не в UTF-8, использована определённая кодировка |

Типичные ошибки и их смысл:

| Сообщение | Причина |
|---|---|
| "Unknown symbol 'x' is referenced here" | неопределённая метка или константа (проверяется также после чтения всего текста, так что ссылки вперёд допустимы) |
| "Duplicate symbol 'x:'" / "Duplicate variable 'x'" | метка или константа определена дважды |
| "numbers are considered base-8 by default…" | число с цифрами 8 или 9 без точки в конце |
| "value … does not fit in … bits" | число слишком велико для `.byte`, `.word` или поля непосредственного операнда |
| "can only jump from … to …" | переход слишком далёк; используйте `jmp` |
| "'x' is an undefined instruction. Did you mean 'y'?" | опечатка в имени инструкции или директивы |
| "This '.word' was emitted on an odd address" | добавьте `.even` после байтовых данных |
| "There is no file at path …" | неверный путь в `.include` или `insert_file` |
