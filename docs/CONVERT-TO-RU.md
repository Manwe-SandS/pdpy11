# convert-to: конвертер исходных текстов

[English](CONVERT-TO.md) · **Русский**

`convert-to` переписывает исходный текст на ассемблере так, чтобы его мог компилировать PDPy11 (или Turbo8). Это
отдельная программа: она входит в каждый архив релиза рядом с `pdpy11`, а собрать её можно командой `make convert-to`.

Для чего она нужна:

* взять исходник для MACRO-11 или Turbo8 с макросами, условной компиляцией и собственными правилами операторов и
  получить обычный код PDPy11, который `pdpy11` компилирует в те же байты;
* проверить, во что на самом деле раскрывается макрос;
* перенести программу с PDPy11 на Turbo8.

```
convert-to [--from=pdpy11|turbo|micro11] pdpy11|turbo  file
```

| Аргумент | Значение |
|---|---|
| `pdpy11` или `turbo` (регистр любой) | диалект, который нужно **получить** |
| `file` | преобразуемый исходный файл |
| `--from=…` | диалект, для которого исходник **был написан**; от него зависит преобразование приоритетов операторов (см. [Операторы](#операторы)). По умолчанию — противоположный целевому. `--from=micro11` дополнительно включает [правила Micro-11](#исходные-тексты-micro-11) |

Результат сохраняется рядом с исходником: к полному имени файла добавляется название диалекта, `prog.mac` →
`prog.mac.pdpy11` (или `prog.mac.turbo`). Оригинал никогда не изменяется. Код возврата: `0` — успех, `1` — исходник
нельзя преобразовать (выводится сообщение с номером строки), `2` — неверная командная строка.

```
convert-to pdpy11 prog.mac && pdpy11 --implicit-bin prog.mac.pdpy11
```

## Как отмечаются изменения

Каждое изменение, которое не совсем очевидно, видно в результате:

* перед изменённой строкой стоит комментарий с исходным текстом: `; was: <исходная строка>`
  (`// was: …` в диалекте Turbo8);
* каждый вызов макроса остаётся строкой-комментарием (`; SetVec	60,KeyIrq`), за которой следует его раскрытие;
* удалённые определения (синонимы регистров, переопределённые константы, неподдерживаемые директивы) оставляют
  поясняющий комментарий;
* предупреждения о том, на что стоит обратить внимание, выводятся в стандартный поток ошибок.

Без комментария меняется только запись символьных констант (`'.` → `"."`): это слишком очевидно.

## Оба направления

### Макросы

Определения `.macro … .endm` удаляются, а каждый вызов заменяется своим раскрытием, так что в результате макросов
нет. Библиотеки макросов, подключённые через `.include`, читаются, чтобы узнать макросы; `.include` файла, который
только определяет макросы, в результат не попадает (файл с настоящим кодом остаётся подключённым). Строки `.mcall`
удаляются. Встроенные макросы `.addr` и `.print` в диалекте PDPy11 раскрываются, а в диалекте Turbo8 остаются
как есть.

```asm
	.macro	SetVec	Vec,Handler,Psw=340
		MOV	#Handler,@#Vec
		MOV	#Psw,@#Vec+2
	.endm
		SetVec	60,KeyIrq
		SetVec	100,Timer,200
```
превращается в
```asm
; SetVec	60,KeyIrq
		MOV	#KeyIrq,@#60
		MOV	#340,@#60+2
; SetVec	100,Timer,200
		MOV	#Timer,@#100
		MOV	#200,@#100+2
```

Семантика макросов (параметры, автоматические метки `?label`, аргументы в `<…>`, апостроф, `.mexit`, вложенность)
описана в [MACROS-RU.md](MACROS-RU.md).

### Условная компиляция и повторения

`.if` / `.iff` / `.ift` / `.iftf` / `.endc` и `.iif` вычисляются во время преобразования, и в результат попадают
только строки истинных ветвей. Блоки `.irp`, `.irpc` и `.rept` раскрываются. Условия: `eq ne gt lt ge le`
(`z nz g l`), `b`, `nb`, `idn`, `dif`, `df`, `ndf`. Значения берутся из констант (`name = number`) и результатов
`.ntype`, которые встречаются **выше** условия, и из аргументов макросов; условие, зависящее от метки, вычислить
нельзя, и преобразование останавливается с ошибкой. Выражения в условиях подчиняются правилам MACRO-11:
`+ - * / & !` стоят на одном уровне и вычисляются слева направо; числа восьмеричные, `5.` — десятичное, допускаются
`^O ^D ^B ^X` и `<…>`.

`.error ;text` превращается в комментарий и дополнительно выводится в стандартный поток ошибок.

### Константы, переопределённые внутри макросов

MACRO-11 позволяет макросу присвоить константе новое значение (`x = 1 … x = 2`); PDPy11 этого не позволяет.
Присваивание заменяется комментарием, а следующие за ним обращения используют действующее значение, записанное
числом (`x` → `2.`).

### Прочее

* Конечные нулевые байты (дополнение файла RT-11) отрезаются.
* Строка без завершающего перевода строки остаётся без него.

## Получение исходника для PDPy11 (`convert-to pdpy11`)

| Что | Изменение |
|---|---|
| Символьные константы | `movb #'.,r0` → `movb #".",r0` |
| Синонимы регистров | объявление Turbo8 `%1 = counter` удаляется (с комментарием), а каждый `counter` превращается в `r1` |
| Комментарии | комментарии `//` и `/* … */` переписываются как комментарии `;` |
| Директивы | `.la` → `.link`; `.insert` → `insert_file` |
| Операторы | смешанные операторы группируются скобками, см. [Операторы](#операторы) |
| `.ascii`, `.asciz` | байты `<15><12>` сохраняются (это не арифметические группы); текст в других ограничителях (`\text\`) записывается в двойных кавычках |
| Имена, начинающиеся с `$` | `$mail` → `S$mail` (PDPy11 не может начинать строку с такого имени после списка слов); все обращения переименовываются |
| `.list`, `.nlist`, `.asect` | удаляются (с комментарием): для PDPy11 они не имеют смысла |
| Метки подряд | `A:B: nop` → `A: B: nop`: PDPy11 требует пробельный символ между метками (`A:B` — это обращение к символу, см. [SYNTAX-RU.md](SYNTAX-RU.md#составные-имена-namen-и-namelabel)) |
| `.radix` | сохраняется: в PDPy11 есть `.radix` (2, 8, 10, 16; без аргумента = 8). Конвертер тоже его учитывает, поэтому условия и счётчики `.rept` вычисляются в правильной системе счисления |
| `Name:Label`, `Name:N` | сохраняются (синтаксис PDPy11) |

```asm
%1 = counter
        mov     #<1+2>*3, counter
        .la     1000
```
`convert-to --from=turbo pdpy11` создаёт
```asm
; register synonym counter = r1: the name is replaced by r1 below
; was: mov      #<1+2>*3, counter
        mov     #(1+2)*3, r1
; was: .la      1000
        .link   1000
```

## Получение исходника для Turbo8 (`convert-to turbo`)

| Что | Изменение |
|---|---|
| Комментарии | комментарии `;` становятся комментариями `//` |
| Директивы | `.link` → `.la`; `insert_file` → `.insert` |
| `.end` | добавляется, если в исходнике его нет (Turbo8 его требует) |
| Директивы, которых нет в Turbo8 | `.once .repeat .dword .odd .error .list .title .extern` остаются на месте и перечисляются в стандартном потоке ошибок, чтобы вы переписали их вручную |
| Операторы | смешанные операторы группируются скобками `< >`, см. ниже |
| `.radix n` | в Turbo8 нет `.radix`: строка становится комментарием, а числа ниже неё, записанные без точки и без префикса, переписываются: система 10 → `12.`, система 16 → `0x1F`, система 2 → `0b101`. Числа с точкой, с префиксом (`0x`, `^O` …) и имена не затрагиваются. `.radix` / `.radix 8` возвращает восьмеричную систему |
| `Name:Label`, `Name:N` | в Turbo8 таких обращений нет: строка остаётся как есть и перечисляется в стандартном потоке ошибок |

## Операторы

Два ассемблера упорядочивают бинарные операторы по-разному (от низшего приоритета к высшему):

| PDPy11 | Turbo8 |
|---|---|
| `\|` | `\|` `^` (один уровень) |
| `^` | `&` |
| `&` | `+` `-` |
| `<<` `>>` | `*` `/` `%` `<<` `>>` (один уровень) |
| `+` `-` | |
| `*` `/` `%` | |

Конвертер разбирает каждое выражение по таблице диалекта, заданного ключом `--from` (по умолчанию — противоположного
целевому), и записывает его для целевого диалекта. Везде, где два порядка дали бы разные результаты, он добавляет
явные группы: `( )` в PDPy11, `< >` в Turbo8, так что значение никогда не меняется:

```
convert-to --from=pdpy11 turbo      mov #1<<2+1, r0    →    mov #1<< <2+1>, r0
```

Группа, содержащая имя регистра, всегда записывается через `< >`, потому что в PDPy11 скобки вокруг регистра
означают косвенную регистровую адресацию.

## Исходные тексты Micro-11

`--from=micro11` учитывает соглашения ассемблера Micro-11 (целевой диалект `pdpy11` или `turbo`):

* **комментарии без `;`.** После мнемоники конвертер считает операнды, которые принимает команда. Если следующий
  за ними текст не начинается с команды, директивы (слова с точкой) или известного макроса, это комментарий, и
  вставляется `;` (`clr r0  clear the register` → `clr r0  ; clear the register`). Хвост, начинающийся с имени команды,
  остаётся кодом;
* **`.+n`** (зарезервировать *n* байт) → `.blkb n`; **`TYIN`** → `emt 6`; **`TOUT`** → `emt 16` (с комментарием
  `was:`);
* **повторно определённые метки.** Micro-11 позволяет определять одну и ту же метку несколько раз; второе определение
  становится `NAME_2`, третье — `NAME_3`, а обращения ниже используют самое новое имя (с комментарием). Обращения
  выше сохраняют прежнее имя;
* **символьные константы** `'AJ'` (два символа, закрытые кавычкой) → `"AJ`, а `'Y'` → `'Y`.

## Ограничения

* Условия могут проверять только константы, определённые выше них, и аргументы макросов, но не метки.
* Макросы с ключевыми аргументами и числовая подстановка `\x` не поддерживаются.
* Макрос должен быть определён до вызова.
* Преобразуются только перечисленные выше различия диалектов; сама программа не анализируется, поэтому смысловые
  различия между ассемблерами (например, детали адресации) не затрагиваются.
* Результат нужно скомпилировать и сравнить со сборкой оригинала: комментарии `was:` сохраняются именно для того,
  чтобы такую проверку было легко провести.
